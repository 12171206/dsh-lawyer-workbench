# 律师工作台 · 设计方案（P1 案件模式）

> 读的是 `律师AI技能包-v1.1-通用版`（217 技能 / 20 分类 / 724 文件），设计的是**律师每天真正会打开的那个界面**。
> 配套：`workbench-1-case.png`（案件台）、`workbench-2-tracks.png`（赛道台）、`lawyer-skillpkg/律师AI技能包-v1.1/catalog.json`（技能目录）

---

## 0. 一句话

**左栏是"台"，台里是"赛道"，赛道里是"阶段"，阶段里才是"技能"。**
律师永远从「我手上这个案子」进入，从「下一步做什么」出来；技能名一次都不需要他看到。

| | 协议 A：`legal-work-control`（21-27 用） | 协议 B：`lawyer-case-workbench`（00 用，已装） |
|---|---|---|

## 2. 三条设计原则

1. **一屏回答三个问题**：这个案子到哪一步了？下一步该做什么？做完的东西在哪？
   → 所以主界面是「阶段流水线 + 下一步动作 + 产出物列表」，不是技能菜单。
2. **律师不选工具，只点下一步**：技能藏在动作卡后面，"开跑"时自动拼上下文（案件路径 + 当前事项 + 目标产物）。
3. **硬闸门变成进度条**：草稿 → 已审 → 已导出 → 已交付。不给律师看错误码，只给"差哪一步 + 一键补"。

## 3. 信息架构：四层

```
L0 台（左栏 5 个图标）
 └─ L1 赛道（9 个业务线 + 1 参考区）
     └─ L2 阶段（每个赛道 6–10 个阶段，与生命周期 Checklist 对齐）
         └─ L3 功能卡（每张卡 = 一个动作 = 1 个技能 + 1 条落盘路径 + 1 道闸门）
```

- 层级固定、可穷举：律师每次点击最多 3 下就到动作。
- **跨赛道共用件**（法律研究、文书起草、交付导出）不重复定义，挂成"横切赛道"，任何赛道的阶段里都能调。

## 5. 功能用途（核心）

### 5.1 先定义"功能"的七种类型

每个功能卡都是这七型之一，类型决定它的界面形态和闸门：

| 型 | 干什么 | 输入 | 输出 | 界面形态 | 闸门 |
|---|---|---|---|---|---|
| ① 建档 | 建案卷、收信息、出手续 | 当事人/案由/管辖 | 目录树 + 基本信息 + 台账 | 表单向导 | 缺必填不建 |
| ② 分析 | 判断能不能打、值不值 | 事实+材料 | 研究报告/策略/胜诉区间 | 报告卡 | 来源边界 |
| ③ 检索 | 找法条、类案、核验 | 法律问题 | 汇编/核验清单 | 结果列表 | 必须核验 |
| ④ 生成 | 写文书、出清单、画图 | 台账+事实 | docx/md/png | 编辑器 | 出稿前审查 |
| ⑤ 检查 | 三性、合规、出稿、台账 | 待检对象 | 命中清单 | 打勾清单 | 不过不交付 |
| ⑥ 推进 | 期限、进展、会议、结案 | 法院文书/时间 | 台账更新 + 下一步 | 时间线 | 只追加不覆盖 |
| ⑦ 交付 | 导出、交付、留痕 | 已审稿 | 正式文件 + 交付清单 | 状态看板 | 四态流转 |

## 6. 界面设计

### 6.1 左栏（`sidebar.panellist`）5 个台

| 图标 | 台 | 主区内容 |
|---|---|---|
| 案 | **案件台** | 案件列表 + 案件详情（三栏） |
| 赛 | **赛道台** | 9 赛道 → 阶段流水线 → 功能卡 |
| 交 | **交付台** | 草稿/已审/已导出/已交付 四列看板 + 交付清单缺口 |
| 期 | **期限台** | 今日/本周/30 天 + 红灯案件 |
| 设 | **设置** | 工作目录、律师画像、参考区、技能管理 |

### 6.2 案件台（三栏）

![案件台](workbench-1-case.png)

- **左：案件列表**——按"期限风险 > 阶段 > 最近活动"排序；每行：案名 / 编号·承办 / 阶段 chip / 倒计时。
- **中：案件详情**——上=案件概况 6 字段；中=「下一步」卡（动作 + 卡点原因 + 3 个按钮：开跑 / 换一个 / 标记完成）；下=本阶段 Checklist（直接勾）+ 台账计数 + 台账校验结果。
- **右：压力面板**——期限与时效（红灯置顶）、交付包 22 项进度与六条红线、本阶段产出物及状态、状态流转条。

### 6.3 赛道台

![赛道台](workbench-2-tracks.png)

- **左：9 赛道**（带技能数、在办数）
- **上：阶段流水线**（横向 10 段，当前段高亮，点段切换）
- **中：功能卡**（每卡：功能名 / 一句话 / 产出路径 / 技能名 / 「开跑」）
- **下：规则条**（输入检查、落盘路径、闸门、留痕——四句话，让律师知道 AI 不会乱来）

### 6.4 界面上必须有的 5 个状态

| 状态 | 触发 | 表现 |
|---|---|---|
| 🟢 绿灯 | 无逾期、交付齐 | 案件行不标色 |
| 🟡 黄灯 | 剩余 ≤ 7 天 / 单项 7 天没动 | 行内黄点 + 数字 |
| 🔴 红灯 | 剩余 ≤ 3 天 / 已逾期 | 行置顶 + 红底 |
| ⚪ 灰 | 已结案 | 折叠进"全部" |
| 🔵 新 | 建档未接案 | "待接案"标签 |

## 7. 数据模型（工作台读什么、怎么算）

### 7.1 目录（沿用已装的 lawyer-case-workbench 协议）

```
<工作目录>/
└── 案件-2026-015-张三诉李四民间借贷/
    ├── 00-案件档案/   基本信息.md · 案件台账.md · 案件生命周期Checklist.md
    │                  期限与时效台账.md · 律师交付包清单.md · 利益冲突审查表.md
    ├── 01-材料收集/   02-证据整理/   03-法律研究/   04-合同审查/
    ├── 05-诉讼策略/   06-文书产出/   07-程序记录/   08-结案归档/
    └── 07-程序记录/案件时间线.md（只追加）
```

### 7.2 界面字段的解析来源

| 界面字段 | 来源 | 解析方式 |
|---|---|---|
| 案名/编号/客户/对方/案由/金额/管辖/承办 | `00-案件档案/案件基本信息.md` | `- 键：值` 行 |
| 当前阶段 | Checklist 最后一个有勾的阶段（基本信息可覆盖） | `## 阶段名` + `- [x]` 计数 |
| 阶段进度 | 各阶段勾选数 / 总数 | 同上 |
| 卡点天数 | `07-程序记录/案件时间线.md` 最后一行日期 | 距今天数 |
| 期限与红灯 | `期限与时效台账.md` 表格 `截止日` 列 | 截止日 − 今天 ≤ 7/3 天 |
| 交付完成率 | `律师交付包清单.md` | `- [x]` / 22 |
| 六条红线缺口 | 同上，固定 6 行 | 未勾项 |
| 台账健康 | `案件台账.md` + `assets/check-ledger.py` | 脚本退出码 + 输出 |
| 产出物状态 | `06-文书产出/`、`07-交付文件/` 文件 + 出稿前审查报告 `review_status` | 文件存在性 + 状态字段 |
| 下一步动作 | Checklist 首个未勾项 + 阶段派发表（SKILL.md §4） | 映射表 |

> 所有解析都是**只读**；写回只有两个入口：勾 Checklist（律师点）、开跑（生成会话），都要二次确认。

## 8. 技能装载策略（这是能不能"不卡"的关键）

| 策略 | 做法 | 常驻成本 | 取舍 |
|---|---|---|---|
| ❌ 全量装 217 | 拷进 `~/.dsh/skills/` | ≈1.7 万 tokens + 40 个脚手架抢入口 | 否 |
| ✅ **精选常驻 + 按需读** | 只装 **9 个 lawyer-\***（已装，自洽）+ **8 个独立工具技能**（法条检索、可视化、出稿审查、模板导出、转换、去 AI 味、材料转文档、Wiki） | ≈1.5k tokens | 是 |
| 其余 50 个中文技能 | 不装，卡片"开跑"时把 `SKILL.md` 绝对路径 + 任务写进会话，模型 `read` 后执行 | 0 | 是 |
| 150 个社区技能 | 参考区折叠，只给"查看原文/复制提示词" | 0 | 是 |

### 8.1 必须先解决的坑：路径断链

包内 21-27 的技能大量硬引用 `skills/legal/legal-work-control/references/*.md`、`.../templates/...`。装到 `~/.dsh/skills/` 后这些路径不存在 → 技能"嘴上说有规则、文件找不到"，会**假装执行**。

处理方案（安装脚本做三件事）：
1. 建 `~/.dsh/skills/_legal-shared/` 放 `legal-work-control/references/*`（协议文件只此一份）；
2. 扫描所有 `SKILL.md` 里的 `skills/legal/...` 路径，改写为共享目录或技能自身目录的绝对路径；
3. 生成 `技能索引.md`（67 条：id / 一句话 / 绝对路径 / 是否带脚本），供工作台和模型共用。

## 9. 技术实现（DSH 插件）

### 9.1 一个插件 `@local/dsh-lawyer-workbench`

照抄已验证的 `plugins/dsh-topic-library` 结构（`package.json` + `cordis.patch.yml` + `index.js` + `client.js` + `locale` + `icon.svg`）：

| 半 | 职责 |
|---|---|
| **Host** `index.js` | 只读扫描案件目录；解析 6 个 md；暴露 REST 路由；"开跑"时用 `sessionController.create + prompt` 建会话 |
| **Client** `client.js` | `sidebar.panellist` 1 个图标；`main` 面板（案件台/赛道台/交付台/期限台）；主题 token 样式；中英 locale |

### 9.2 Host 路由

| 方法 | 路径 | 返回 |
|---|---|---|
| GET | `/lawyer-workbench/api/cases` | 案件列表（含阶段、红灯数、交付率） |
| GET | `/lawyer-workbench/api/case?id=` | 单案详情（概况/Checklist/期限/交付/产出/下一步） |
| GET | `/lawyer-workbench/api/deadlines` | 期限聚合（今日/本周/30 天） |
| GET | `/lawyer-workbench/api/skills` | 67 条技能目录（来自 catalog.json） |
| POST | `/lawyer-workbench/api/open` | `{caseId, actionId}` → 建会话 + prompt，返回 sessionId |
| POST | `/lawyer-workbench/api/check` | `{caseId, itemId, done}` → 勾 Checklist（写前返回 diff 供确认） |

### 9.3 "开跑"的提示词模板（律师看不到，但要稳定）

```
用 <技能名> 处理案件「<案件名>」（路径：<案件绝对路径>）。
当前阶段：<阶段>；本次目标：<功能名>；产出落盘到：<路径>。
先读：00-案件档案/案件基本信息.md、案件台账.md、本阶段 Checklist。
要求：不覆盖已有文件；法条与案号必须核验；产出首行写编号并回填「关联文件」。
```

## 11. 风险与边界

| 风险 | 对策 |
|---|---|
| 演示案件跑通≠真实案卷跑通（律师的 md 可能没按模板填） | 解析器全部"容错 + 显示未知"，缺字段显示"未填"，不崩；P1.0 就加 |
| 期限计算涉及法律判断（起算点、期间） | 界面只显示"台账里写的截止日"，不自己算法定期限；红灯只是提醒 |
| 勾选写回可能误改 | 写前返回 diff 确认；只允许改 Checklist 勾选与时间线追加，不碰正文 |
| 参考区误用 | 无"开跑"按钮；卡片标"非中国法"；需要时二次确认 |
| 两套目录协议并存 | P1 只认 lawyer-case-workbench 协议；21-27 技能按需读，不改目录 |
| 飞书看板 | 本期不接；`case-board.py` 保留，等验收后作 P2 可选项 |
